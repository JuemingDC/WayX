# WayX Rule Sets

Python aggregates the registered upstreams into native Quantumult X and Surge lists. Source authors, URLs and licenses are recorded in `.github/sources/rules.json`; source checksums and generated output counts are recorded in `.github/sources/rules-state.json`.

## Categories

- `adblock`: 217heidai + limbopro, merged with same-policy domain coverage deduplication.
- `adblock_extra`: optional incremental Sukka base domains. Keep this disabled unless extra filtering is wanted.
- Named applications: Google, Facebook/Meta, Netflix, Disney, YouTube, Telegram, X, Spotify, GitHub, OpenAI, Apple and Microsoft.
- `media`: other overseas applications, including non-video services.
- `media_cn`: domestic applications.
- `proxy` and `cn`: broader fallback lists. A profile still needs a final/default policy for unmatched requests.

Only direct blackmatrix7 inputs are excluded. Other maintainers' upstream choices are accepted. MetaCubeX generated categories and its own supplements are used alongside the official V2Fly release. SagerNet's official geosite builder consumes the same V2Fly release, so that identical input is downloaded only once and verified against its official SHA-256 checksum.

## Policies and order

Quantumult X lists carry per-rule policies. Create policy groups named `google`, `facebook`, `netflix`, `disney`, `youtube`, `telegram`, `x`, `spotify`, `github`, `openai`, `apple`, `microsoft`, and `Media`, or adapt those names in the registry. Use your normal `proxy` policy group for broad proxy rules; `direct` and `reject` retain their native actions. Do not apply `force-policy` to mixed direct/proxy application lists. Every REJECT-family action is emitted as `reject`.

Surge lists omit policy fields. Reference each list with RULE-SET and the desired policy. Apple and Microsoft have separate `_direct` and `_proxy` lists. Other mixed-policy categories are split the same way. Proxy rules use native AND/NOT exclusions where needed so a more-specific direct exception remains effective even when the proxy list is installed before a broad brand-direct list. Rejection variants retain separate Surge lists if an input supplies them.

Apply personal exceptions and local-network handling first, then advertising rules, named applications and their direct exceptions, media/media_cn, and broad proxy/cn fallbacks. YouTube precedes Google; GitHub precedes Microsoft; specific brand proxy exceptions precede broad brand-direct rules. Put direct exceptions before broader conflicting proxy rules. Match domain rules before resolving general IP/GEOIP fallbacks. Shared CDN names are not assigned to an application solely from corporate ownership. Keep direct and proxy fallbacks ordered according to your intended policy; overlaps are not a proof of a universally correct route.

## Automation and limitations

The existing Action downloads registered inputs, groups and deduplicates rules, generates both targets, replays the build and validates all generated bytes and metadata. Timestamps change only when that output changes. Source download/checksum failures prevent publication; incomplete builds preserve the previous outputs. Stale configured feeds and unexpected large reductions fail validation.

Unsupported domain regular expressions are quarantined instead of being widened into wildcard rules. Native process rules are retained for Surge and quarantined for Quantumult X. Matching declarations already covered by a provable literal domain suffix do not need an additional regex rule. Unknown fields and ambiguous ownership are reported through managed Issues; full source declarations are saved in `rules-result.json` in the Action artifact. Supported declarations can continue to publish while these explicitly reported exceptions await review.

This collection preserves upstream classifications; it is not an independent guarantee that every upstream entry is accurate or that a large union has fewer false positives. This routing collection does not replace response-rewrite plugins or browser cosmetic filtering. Existing hand-maintained files are not overwritten or pruned by the aggregator.
