## 三端映射

| 能力 | Quantumult X | Surge | Loon（Script v2 声明） | 当前处理和剩余边界 |
| --- | --- | --- | --- | --- |
| 请求 URL/方法 | `$request.url/method` | 同名字段 | 同名字段 | 受限静态字段已支持；对象外传、动态成员须追踪 |
| 输入响应状态 | `$response.statusCode` | `$response.status` | `$response.status` | 输入状态映射；不能混淆输出字段格式 |
| 文本主体 | `$request/$response.body` | 同名字段 | 同名字段 | 保持 String；声明须等待正确阶段正文 |
| 二进制主体 | `bodyBytes: ArrayBuffer` | `body: Uint8Array` | `body: Uint8Array` | 明确 binary/等待正文声明，保留切片偏移；不由文本猜字节 |
| Header | `headers` 对象 | `headers` 对象 | `headers` 对象 | 已支持只读 singleton 查找；重复值、大小写、修改/删除与 framing 未普遍证明 |
| 正常完成 | `$done(result)`；已证明 response-body 可 String | `$done(result)` | `$done(result)` | 有限结果流已支持；不能推广所有阶段的无参/空对象/字符串结果 |
| 修改状态 | 结果 `status` 为 HTTP 状态行 | 结果 `status` | 结果 `status` | 通过公共状态表示转换；只在已证明的结果域生成 |
| 请求直接响应 | script echo 相应结果 | request 结果的 `response` | request 结果的 `response` | 区分放行/修改/合成，按声明验证，不能仅替换 `$done` 名称 |
| 额外 HTTP | `$task.fetch` Promise | `$httpClient` callback | `$httpClient` callback | 七方法、受限成功/错误流已支持；扩展闭合别名与异步链 |
| 请求选项 | `opts` 已说明字段 | 原生选项；timeout 秒 | 原生选项；timeout 毫秒 | 映射 cookie/redirect/TLS/policy；QX 未说明参数省略、不报错，仍求值原表达式 |
| 存储读取 | `$prefs.valueForKey(key)` | `$persistentStore.read(key)` | `$persistentStore.read(key)` | 缺失值只在调用者观察等价时归一；不能宣称不同客户端共享同一存储 |
| 写入/删除 | `setValueForKey` / `removeValueForKey` | `write(value,key)` | `write(value,key)` | 已证明字符串与删除；Loon pristine stringify 的 undefined 可映射删除；动态键/空值需证明 |
| 插件参数 | 不提供对应 `$argument` | `$argument` String | String 或 typed PluginObject | 已有 schema/payload 才解码 Surge JSON；QX 省略并验证作者安全默认分支，不重造保存设置 |
| URL fragment 参数 | `$environment.variables`（作者说明 build 918+） | 需显式声明/已验证解析方式 | 需显式声明/已验证解析方式 | 与保存的 PluginObject 不同，不能默认互换；新入口映射尚未实现 |
| 通知 | `$notify` | `$notification.post` | `$notification.post` | 三文本字段已支持；附件、动作、延迟按字段补，QX 未说明参数省略 |
| 名称/启动时间 | 无已证明的全等同名入口 | `$script.name`、epoch 秒 startTime | `$script.name`、Date startTime | 名称有限支持；时间必须从真实输入换算，不用 Date.now 伪造源开始时间 |
| 软件身份 | 实际 QX 环境 | 实际 Surge 环境 | `$loon` 设备/版本 String | 可证明的纯存在性分支可裁剪；不能伪造 Loon 版本 |
| UTF-8/Base64 | 局部共同实现 | 局部共同实现 | 局部共同实现 | 直接闭合调用已支持；扩展静态别名需证明；其它编码和反射仍阻断 |
| 定时器 | 作者示例有 setTimeout | 逐项核对调度/取消/结束生命周期 | 文档 setInterval 只执行一次，clear 配对不可靠 | 同名不等于同调度；不能以空函数或重复 timer 代替，尚无通用取消契约 |
| WASM/压缩/加密 | 逐算法建立证据 | 逐算法/引擎建立证据 | WASM 引擎；gzip/AES 独立接口 | WASM 目前仅无执行检查；不能用 require、空 exports 或异步 WebCrypto 替代同步调用 |

依据：[QX rewrite](https://github.com/crossutility/Quantumult-X/blob/master/sample-rewrite-with-script.js)、[QX HTTP/fragment](https://github.com/crossutility/Quantumult-X/blob/master/sample-task.js)、[QX bytes](https://github.com/crossutility/Quantumult-X/blob/master/sample-bytes-rewrite.js)、[Surge API](https://manual.nssurge.com/scripting/api.html) 和 HTTP request/response 类型页、[Loon Script v2](https://nsloon.app/docs/Script/script_v2/)、[Loon Script API](https://nsloon.app/docs/Script/script_api/)。Script v2 是声明语法，运行时 API 仍以 Script API 页面为准。两份 Loon 文档对无参数分别描述 null 与可能 null/undefined；在来源不确定时仍不允许严格缺失观察推断。

ScriptHub 比较继续使用能力报告中的固定修订 b943361f11be5795b3eb10f9cc4e5497642922fc；本轮没有重新宣称上游版本更新。其前置兼容层可供结构参考，但小写 Header Proxy、GET/POST 二分、timer no-op、失败变成功及文本替换不作等价依据。

## 优先级与收益依据

基线为发布提交 91bd34f：143 个通用脚本、804 处引用；剩余 80 个源 URL、545 处引用阻断。以下按 API 家族合并，不同于单条问题数量，家族之间重叠，不能相加。

| 顺序 | 家族 | 受影响源数 | 仅该家族阻断的候选数 | 决策 |
| --- | --- | ---: | ---: | --- |
| P0 | 来源 profile/语法/字节前提 | 5 | 4 | 先区分源无效、缺件和声明歧义；代码修复不一定能解决 |
| P0 | 框架接收者、对象别名和数据流 | 45 | 7 | 公共分析基础；先审查 7 个候选，再扩展闭合框架 |
| P1 优先 | Header | 22 | 11 | 独立候选最多；先只读/静态修改，再重复字段和 framing |
| P1 优先 | 存储 | 24 | 2 | 先固定键表达式和只作 String 使用的读值 |
| P1 | 参数 | 16 | 1 | 先检查省略后的执行路径；Spotify 候选不能靠 catch 放行冒充成功 |
| P1 | 完成结果 / HTTP | 22 / 25 | 0 / 0 | 配合数据流和 Header 实现；单补名称映射不会立即解除整脚本阻断 |
| P1 按需 | 编解码 / 二进制 | 26 / 6 | 0 / 0 | 优先解决已明确业务操作；编码与引擎家族共同阻断 19 个源 |
| P2 | 通知 / 环境 | 18 / 21 | 1 / 0 | 通知可有小切入点；环境身份不能按收益数字伪造 |
| P2 | 定时器与生命周期 | 每次报告统计 | 每次报告统计 | 区分实际 timer 调用和未使用框架定义；保留回调次数与完成时机 |
| P3 | 引擎、WASM、压缩等 | 29 | 0 | 按模块摘要与实际操作分组，成本高且不能一层通用 shim 解决 |

“仅该家族”仅表示现有诊断没有其它家族，不承诺补齐后一定通过；家族内部可能包含多个不兼容操作，分析增强也可能发现新问题。未分类问题始终保留 other，不删除以美化统计。先做 P0 数据流，再以 Header 的独立候选和存储小域推进，比按报错条数从大到小放行更可控。

## 实现和验证

`src/parser/script-api-mapping.ts` 保存 API 对应、当前支持域、依赖与下一步方案；纯函数 `scriptConversionPriorities` 按所有 target/profile 的阻断并集去重源 URL，输出 affectedSources、singleFamilyCandidates 和 coBlockers。`src/application/script-api.ts` 在现有事务报告加入 apiMapping/conversionPriorities，原有 diagnostics、capabilities 和成功/阻断计数保持原语义。没有改写作者 JS 或放宽发布门槛。

`tests/script-api-mapping.ts` 验证跨 profile/target 去重、共同阻断、单家族候选、未知诊断和排除范围。既有备份事务回归检查新报告与正常发布共存。仅 Actions 生成实际报告并发布；每次上游变化自动重算优先级。方案与分析已落地，后续 API 实现按上述子域逐项推进。
