## 目标与方向

只处理去广告 HTTP request/response/echo 脚本。生产方向固定为 Loon→Quantumult X、Loon→Surge、Quantumult X→Surge。来源原生执行保留，但不增加反向转换。每个源 URL 一个同源命名的共用 JS，业务正文一次；来源原件逐字节备份，来源信息和诊断放在外部索引。

## 转换链路

1. AST 按词法绑定收集具体 API、成员路径、访问类型和位置；不执行作者代码。
2. `src/domain/script-api.ts` 定义宿主布局和具体语义操作。`src/parser/script-api-ir.ts` 将每次调用或字段观察转换为 ScriptApiIR，记录原 API、规范操作、目标 API、逐字段变换和证明结果。
3. 既有数据流分析验证值类型、闭合引用、声明上下文和副作用。名称能匹配规则不代表任意输入已证明安全。
4. `src/emit/script-api-plan.ts` 从同一宿主布局生成轻量执行计划；共同运行时按计划处理状态字段、存储、通知、HTTP 默认值和单位、完成值及字节视图。完整位置记录不注入业务 JS。
5. Actions 同事务更新原件、共用脚本、引用、逐操作计划及状态。源更新未获证明时保留已验证版本并报告差异。

## 具体转换的对应

| 来源内容 | 规范语义 | 目标处理 |
| --- | --- | --- |
| QX `$response.statusCode` | 数字 HTTP 状态 | Surge `$response.status` |
| QX `$prefs.removeValueForKey(key)` | 删除单键 | Surge `$persistentStore.write(null,key)` |
| Loon `$persistentStore.write(null,key)` | 删除单键 | QX `$prefs.removeValueForKey(key)` |
| Loon `write(undefined,key)` 的已证明删除路径 | 删除单键 | Surge 写入 null 删除标记；QX 单键删除 |
| Loon HTTP timeout | 毫秒 | Surge 秒；QX 无文档参数省略 |
| HTTP redirection/cookie/TLS/policy | 请求控制及来源默认值 | 按宿主字段、默认值和策略名生成选项 |
| QX echo 完成对象 | 合成 HTTP 响应 | Surge response 包装，状态格式转换 |
| Loon 通知 openUrl/mediaUrl | 打开地址和媒体 | Surge url/media-url；QX 可选参数省略 |
| 正文/字节视图 | 文本或精确范围字节 | 按输入声明、类型和宿主字段分派 |

每次调用记录 argument 与 option 的对应、被省略项及类型分派。QX 作者未文档化的参数无错省略，保留原构造表达式副作用；来源 QX 的未说明参数也不能在 Surge 分支重新生效。动态未知方法不猜成 GET。此表仅是例子，权威细则在可执行目录。

## 每源计划与位置

`Resource/Backup/script-api/<源URL SHA-256>.json` 使用稳定 URL 身份。记录原件 SHA、原始语法引用，以及按请求阶段/目标分开的语义计划。原始语法位置绑定 decoded source 摘要；特化后的语义位置绑定 analysisSourceSha256，sourceView 为 analysis-input。位置采用 UTF-16 offset 和行列，不将特化位置冒充原件坐标。

`index.apiPlans` 记录路径、计划摘要和原件摘要；验证器校验 URL 路径、文件摘要、当前原件绑定和授权方向。摘要不一致报 api-plan-integrity。旧无计划索引仅用于迁移，不能制造新成功记录。

## 扩展规则的步骤

先找真实归档脚本的具体用法，确定来源契约和目标行为，再为规范操作添加规则及字段映射。复用同一个宿主布局，禁止另建软件拼写/默认值表。补充需要的数据流证明；以同一输入测试计划记录和实际目标 SDK 调用，增加有意义的反例。最后通过现有 Actions 更新真实产物，并比较新旧通过、阻断和保留数。

family 优先级仅是按源合并的工作排序；具体 API 名称由操作目录派生。证明器负责适用域，目录和执行计划负责宿主差异，不以单脚本字符串替换或白名单作为转换支持。

## 能力边界

现有证明域外的动态对象、反射、Header 写入/重复字段与 framing、实际运行身份、无法确定的参数默认路径、WASM/压缩仍可阻断。语法引用仍要列出，已识别操作应给出具体规则和所需证明；没有映射记录 unmapped，不制造空实现。VM 执行证据不是实机认证。本轮统一转换基础设施不等于解除全部历史阻断，也不以计划数量当成功文件数。

语法识别与来源可用性必须分开：跨软件框架可以含有其它宿主的分支。已知 API 拼写从共同目录识别；来源没有的 SDK root 使用目录生成的 source.absent 规则，保留 undefined 绑定与原分支求值，不调用目标 SDK。逐操作记 source.unavailable-binding，不能将它宣传为该 API 已获得来源支持。

## 通知与原响应的具体规则

Modified: 2026-11-02 (chance). `omitScriptNotificationOptions` 根据共同宿主目录推导执行计划；来源或目标采用 QX 三文本通知契约时，附加参数构造后省略。QX 原生共用分支仅在实际存在通知省略记录时使用三参数转发，保留原构造副作用和异常，规则不推广为其它宿主无错接受未知参数。

`script-original-context.ts` 独立证明 QX 文本 response-body 的直接原响应返回：所有同上下文引用仅为 presence、标量 body/statusCode 读取或直接完成调用，无别名、Header/字节访问、逃逸或写入，并且 $done 没有重绑定/间接观察。审查括号、解构、循环、delete/update。目录以 original-context selector 选择 complete.pass-original；逐调用记录目标 Surge 空修改完成，原生 QX 保留原对象返回。运行时仅对已证明的原 view 身份放行，正常对象仍走原完成字段逻辑。单次 AST 证明结果复用于逐操作解析，避免每调用重新遍历源码。

两类能力各有真实原件、正反例和实际宿主 SDK 执行验证，并在隔离备份事务中组合验证三个源 URL、同源文件名和两端固定引用。它不提供任意上下文修改或通知 rich options 等价。
